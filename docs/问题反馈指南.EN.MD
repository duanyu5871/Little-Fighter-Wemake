# How to Report a Problem

[中文](./问题反馈指南.MD) | [English](./问题反馈指南.EN.MD)

A report that can be handled quickly = **version + environment + steps to reproduce + expected/actual + evidence**, **given all at once**. Don't drip-feed information one message at a time — a complete report gets handled much faster.

**Where to post**: opening a **GitHub Issue** is preferred → <https://github.com/gimhol/Little-Fighter-Wemake/issues> (easy to track, easy to add more information later). If you're not sure whether it's a bug, or want to discuss first, use [Discussions](https://github.com/gimhol/Little-Fighter-Wemake/discussions) or the group chat. Search for an existing report first — if there is one, add your details to it.

**Feedback is very welcome**: there aren't many reports yet, so **every single one gets read**. Don't hesitate because the problem seems minor, you can't tell what went wrong, or you're unsure whether it counts as a bug — post it anyway. This guide exists only to make problems easier to pin down, not as a barrier to entry.

**Attach a GIF or a screenshot whenever possible** — a few seconds of "input → problem" is worth more than a paragraph; [ScreenToGif](https://www.screentogif.com/) (Windows, free and open source) records the screen and exports a GIF directly.

The sections below explain what to include and how to get it. Partial info is fine — just try not to skip **version and reproduction steps**.

## 0. Three quick checks first

Many "problems" come from caching or the environment. Rule those out in a minute:

- **Hard refresh** and try again: `Ctrl + F5` (Mac: `Cmd + Shift + R`), or open an incognito window.
  An old page combined with a new data pack is the most common source of "weird behavior".
- **Try the official data**: if you replaced the data pack, used "Custom Game", or installed custom fighters, reproduce with the official data first.
- **Try another browser/device**: this separates "a problem everyone has" from "a problem on your side".

## 1. Version info (required)

- The bottom of the launcher/main page shows a line like:

  ```
  v0.1.51-59c3450-dirty 2026-09-19 22:51:28
  ```

  Include the build time as well (a screenshot works too).
- Say which build you play:
  - Release (lf.gim.ink)
  - Preview (GitHub Pages)
  - Chrome extension
  - Bilibili Toy

Different builds mean the problem may already be fixed, or may not even exist in the same code.

## 2. Environment (required)

- **OS**: Windows 10/11, macOS, Android (version), iOS (version)…
- **Browser**: Chrome 141 / Edge / Firefox / Safari … (on mobile, name the exact browser/app)
- **Input**: keyboard / on-screen gamepad

## 3. Steps to reproduce (most important)

The goal is for someone else to reproduce it **by following your steps**. Include:

- **Mode**: Stage / VS / Survival Rank (solo or 2P) / Online
- **Stage/map**: e.g. "white snow map", "survival wave 5"
- **Fighter & move**: e.g. "Henry's arrow", "Julian D>A"
  - Character, move and item names are **not the same in every language or region** (the same move can have completely different nicknames in different communities), so describe a move with the **key combo** (e.g. `D>A`) or mark it on a screenshot — that way there is no mismatch.
- **Numbered steps**: `1. … 2. … 3. …`
- **Expected result** vs **actual result**
- **Frequency**: every time? once every few matches? For intermittent issues, describe when it tends to happen

If you have a **GIF/video**, a 5-second clip beats a paragraph. For GIFs, [ScreenToGif](https://www.screentogif.com/) is recommended (Windows, free & open source, exports GIF directly); the built-in recorder on other platforms is fine too:

- Windows: `Win + G` or `Win + Alt + R`
- macOS: `Cmd + Shift + 5`
- Mobile: the system screen recorder

## 4. Evidence (attach if available)

- **GIF / screenshot**: error dialogs, black screen, white boxes, wrong numbers, misplaced graphics… a GIF is even better (recommended: [ScreenToGif](https://www.screentogif.com/))
- **Console errors** (desktop): `F12` → `Console` panel → **copy the red text** and paste it (a screenshot is fine too)
  - Don't worry about understanding it — paste it all, it will be filtered
  - Mobile browsers don't have a console; just describe your device and what happens
- **Stutter / low FPS**: turn on「Perf」in Settings, then screenshot the FPS/latency it shows
- **Online desync**: say whether "only one player lags" or "everyone lags", and what each side sees

## 5. Please call out these cases

- **A data pack from elsewhere / modified fighters**: say so up front — otherwise it is most likely not an engine problem
- **Playing a preview build or a specific tag**: the problem may already be fixed
- **Bilibili Toy vs web differences**: mention that you play inside Bilibili
- **"It feels different from the original"** (handling, timing, combos — subjective feel): read [Thoughts on the differences from LF2](./对于与LF2表现差异的看法.EN.MD) first; such reports are welcome too — just describe what exactly feels different
- **Intermittent problems**: tell roughly when it started (e.g. "after playing for half an hour") and what you did before

## 6. Copy-paste template

```
Version: v0.1.51-XXXXXXXX (release / preview / extension / Bilibili)
Environment: Windows 11 + Chrome 141 / keyboard
Mode: Survival Rank (solo)
Fighter: Louis, run-attack (electro shock)
Steps:
1. Enter Survival Rank and pick Louis
2. Use the run-attack on an enemy
3. The enemy stays still after being shocked
Expected: the enemy should be stunned by the shock
Actual: the enemy doesn't move at all, and there is no effect either
Frequency: every time
Attachments: GIF/screenshot: xxx; no console errors
Notes: no modified data pack
```

## 7. Tips

- **Give all the information in one report**: version, environment, steps and evidence at once — don't just post "there is a bug" and wait to be asked
- **One problem per report** — don't stuff five problems into one thread
- Follow-ups (e.g. "it no longer happens after updating") should be added to the **same thread**, not a new one
- If the author asks for details (a specific version, a log), please reply — such problems are usually one piece of information away from being fixed
- "It doesn't behave like the original LF2" is not necessarily a bug — see [Thoughts on the differences from LF2](./对于与LF2表现差异的看法.EN.MD)
